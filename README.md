# GT-DOS

[English](README.md) | [简体中文](README.zh-CN.md)

GT-DOS is a small, from-scratch **x64 teaching operating system** written in NASM assembly and C
(compiled with clang/LLVM). It boots from a single 64 MB hard disk image through its own MBR and
second-stage loader into 64-bit long mode, and provides a text console, a graphical desktop,
a FAT16 file system, user accounts and a bilingual (Chinese/English) shell.

![version](https://img.shields.io/badge/version-0.7-blue)

## Features

**Boot**
- Custom MBR (`boot/mbr.asm`) with a hand-written partition table
- Second-stage loader (`boot/boot.asm`) that loads the kernel with ATA LBA reads (AH=42h / DAP)
- Kernel loaded at `0x10000`, hard cap of 256 KB

**Kernel**
- 16-bit real mode → 32-bit protected mode → **x64 long mode**, all in `kernel/entry.asm`
- Identity page tables built in 32-bit mode (PML4 + PDPT + 2 MB large pages)
- Full 1 GB UC MMIO window mapped so the framebuffer is reachable
- IDT with 16-byte x64 gates, ISR stubs, SysV-compliant register save/restore
- APIC + IO-APIC with interrupt priority (TPR) and vector classes
- Softirq pattern: top half only buffers input, bottom half decodes in the idle loop
- ATA PIO driver, FAT16 file system, serial console (UTF-8)

**Graphics**
- Bochs VBE linear framebuffer, LFB address discovered through PCI configuration space
- Double buffering — every draw goes to a back buffer, then flips, so there is no flicker
- Runtime resolution switching: 640x480 / 800x600 / 1024x768 / 1280x1024
- GUI desktop with windows, drag, title bars, icons and a taskbar

**Fonts**
- 16x16 grayscale CJK glyphs rendered at native 14 px with GDI `CLEARTYPE_QUALITY`
- 4 bits per pixel, 16 alpha levels, blended against the background at draw time
- ~21,500 glyphs (ASCII, Latin, symbols and CJK) sharing one baseline, so Latin and
  Chinese text sit on the same line
- Generated by `tools/mkfont.py` into `build/font.bin` (2.75 MB) and `cpm.bin`

**System**
- OOBE first-boot wizard (language → hostname → administrator → theme)
- User accounts with passwords; `admin` holds administrator privileges
- i18n layer with complete Chinese and English strings

## Quick Start

### Requirements

| Dependency | Notes |
| --- | --- |
| Windows | The build script and font generator use Win32 APIs |
| Python 3.8+ | Runs `build.py` and `tools/mkfont.py` |
| NASM | `nasm.exe` on `PATH`, or in `C:\Program Files\NASM` |
| LLVM / clang | `clang.exe`, `ld.lld.exe`, `llvm-objcopy.exe` in `D:\LLVM\bin` or `C:\Program Files\LLVM\bin` |
| QEMU | `qemu-system-x86_64.exe` in the `qemu/` directory, or on `PATH` |

`build.py` searches the locations listed in `CANDIDATES`; adjust that table if your toolchain
lives somewhere else.

### Build and run

```sh
python build.py            # compile, producing build/gt-dos-hd.img
python build.py run        # boot the image in QEMU
python build.py run -nogui # serial console only, no graphics window
python build.py run -debug # boot with CPU/interrupt tracing enabled
python build.py all        # build, then run
python build.py clean      # remove the build directory
```

The first build also generates the font: `tools/mkfont.py` is invoked automatically when
`build/font.bin` or `build/cpm.bin` is missing, which takes noticeably longer than later builds.

To boot the released image directly:

```sh
qemu-system-x86_64 -hda gt-dos-hd.img -boot c
```

On first boot the OOBE wizard asks for language, hostname, administrator name and theme.
Empty input re-prompts; `Ctrl-C` skips a step with its default value.

## Disk Layout

The image is a single 64 MB raw hard disk with an MBR partition table:

| Region | Location | Contents |
| --- | --- | --- |
| MBR | LBA 0 | `boot/mbr.asm`, partition table written by `build.py` |
| Partition 1 (C:) | LBA 2048, 120832 sectors | FAT16 system volume, holds `\GT-DOS\` and the `INCLUDE` headers |
| Partition 2 (hidden) | last 8192 sectors | Boot partition, type `0x11`, bootable: `boot.bin` + `kernel.bin` + `font.bin` + `cpm.bin` |

The boot partition sits at the end of the disk and carries the bootable flag; the kernel reads
`font.bin` and `cpm.bin` from it at boot time over ATA.

## Shell Commands

Type `HELP` (or `?`) inside GT-DOS for the full list. Commands support both long and short names.

**System** — `HELP`/`?`, `VER`, `CLS`, `DATE`, `TIME`, `MEM`, `CPUID`, `UPTIME`, `BEEP`,
`COLOR`, `SERIAL [OFF]`

**Users** — `WHOAMI`, `USERS`, `LOGIN`, `LOGOUT`/`EXIT`, `PASSWD`, `USERADD`, `USERDEL`,
`HOSTNAME`, `CONFIG`, `OOBE` (administrator privileges required for `USERADD`, `USERDEL`,
`HOSTNAME`, `SHUTDOWN` and `REBOOT`)

**Files and disks** — `CD`, `PWD`, `DRIVES`, `DIR`/`LS [/A]`, `TYPE`/`CAT`, `PUT`, `DEL`/`RM`,
`MKDIR`/`MD`, `RMDIR`, `TOUCH`, `ATTRIB`, `CP`/`COPY`, `MV`/`REN`, `HEAD`, `WC`, `TREE`,
`DF`, `DISK`, `MOUNT`

**Graphics and hardware** — `GUI`, `RES <W>x<H>` / `RES LIST`, `APIC`, `IRQSTAT`

**Power** — `REBOOT`, `SHUTDOWN`/`POWEROFF` (administrator privileges required)

## Project Structure

```
boot/
  mbr.asm            MBR, loads the second stage
  boot.asm           second-stage loader, loads the kernel and passes metadata
kernel/
  entry.asm          real mode -> protected mode -> long mode, page tables
  isr.asm            interrupt stubs and the common register frame
  kernel.ld          linker script; large buffers live in .highbss above 1 MB
  gt.h               kernel-wide definitions
  include/           system headers (stdio.h, stdlib.h, string.h, gtos.h)
  kmain.c            kernel entry
  idt.c apic.c isr    interrupts: IDT, APIC/IO-APIC, dispatch
  timer.c keyboard.c mouse.c serial.c    devices
  softirq.c          deferred work for input bottom halves
  ata.c fat.c cfg.c user.c               storage, file system, config, accounts
  gfx.c vga.c tui.c console.c ui.c       graphics layer, text console, splash
  gui.c              graphical desktop
  shell.c            command interpreter
  i18n.c power.c oobe.c lib.c            strings, reset/poweroff, first-boot wizard
tools/
  mkfont.py          font generator (GDI -> 4-bit grayscale font.bin + cpm.bin)
  test_v03.py        end-to-end test: OOBE, login, file commands
  test_v04.py        regression: single C: disk, GT-DOS directory, attributes, protection
  verify_gui.py      screenshot-based GUI verification
build.py             build script and image assembler
```

The test scripts drive a QEMU instance over a serial socket and a QEMU monitor socket, so they
assert on real boot output rather than on mocks.

## Notes and Limitations

- The kernel currently fits in 198 sectors (100,992 bytes), loaded between `0x10000` and `0x80000`.
  Growing past that window requires relocating the load address.
- Large zero-initialised buffers (`font_buf`, the code page table, the back buffer) are placed in
  a `NOLOAD` `.highbss` section above 1 MB. If they were in ordinary `.bss` they would overlap the
  `0xA0000` VGA aperture and corrupt the framebuffer.
- Building requires Windows; the kernel itself is fully freestanding and does not depend on the
  host platform.
- A license has not been declared for this project yet.
