# GT-DOS

[English](README.md) | [简体中文](README.zh-CN.md)

GT-DOS is a small, from-scratch **x64 teaching operating system** written in NASM assembly and C
(compiled with clang/LLVM). It boots from a single 64 MB hard disk image through its own MBR and
second-stage loader into 64-bit long mode, and provides a text console,
an exFAT file system, a TCP/IP network stack, user accounts and a bilingual
(Chinese/English) shell.

![version](https://img.shields.io/badge/version-0.10-blue)

## Features

**Boot**
- Custom MBR (`boot/mbr.asm`) with a hand-written partition table
- Second-stage loader (`boot/boot.asm`) that loads the kernel with ATA LBA reads (AH=42h / DAP)
- Kernel loaded at `0x10000`, hard cap of 256 KB
- The kernel image is a protected container: a `GTK1` trailer records length, CRC32 and
  SHA-256, and the first C statement verifies the loaded image before any other code runs
- Kernel code and read-only data are mapped with 4 KB pages and RW cleared, so they cannot
  be written even in ring 0; an idle watchdog re-checks that range every 5 seconds
  (`GTR1` CRC32) and halts the system on a mismatch

**Kernel**
- 16-bit real mode → 32-bit protected mode → **x64 long mode**, all in `kernel/entry.asm`
- Identity page tables built in 32-bit mode (PML4 + PDPT + 2 MB large pages)
- Full 1 GB UC MMIO window mapped so the framebuffer is reachable
- IDT with 16-byte x64 gates, ISR stubs, SysV-compliant register save/restore
- APIC + IO-APIC with interrupt priority (TPR) and vector classes
- Softirq pattern: top half only buffers input, bottom half decodes in the idle loop
- ATA PIO driver, exFAT file system (long names, allocation bitmap, FAT chains), serial console (UTF-8)

**Graphics**
- Bochs VBE linear framebuffer, LFB address and VRAM size discovered through PCI configuration space
- Automatic resolution selection: 1920x1080 first, then 1024x768 / 800x600 / 640x480 when the
  mode or the available VRAM does not fit
- Windowed runs are capped to the host work area (written into the kernel by `build.py`), so the
  QEMU window is never clipped by the taskbar; `run -full` lifts the cap and lets QEMU scale
- Integer font scaling (1x-3x) chosen so the text grid fills the screen, e.g. 120x33 cells at
  1920x1080 with 2x glyphs
- Double buffering — every draw goes to a back buffer, then flips, so there is no flicker
- Text console soft-rendered on the framebuffer, so Chinese is not limited to the VGA 256 slots

**Fonts**
- 16x16 grayscale glyphs rendered at native 16 px with GDI `CLEARTYPE_QUALITY`, filling the cell
- 4 bits per pixel, 16 alpha levels, blended against the background at draw time
- ~21,400 glyphs (ASCII, Latin, symbols and CJK) sharing one adaptive baseline, so Latin and
  Chinese text sit on the same line
- Generated by the Rust tool `rust/mkfont` into `build/font.gtd` (2.75 MB) and `cpm.gtd`

**System**
- OOBE first-boot wizard (language → hostname → administrator)
- User accounts with passwords; `admin` holds administrator privileges
- i18n layer with complete Chinese and English strings

  the first three follow the original ABI, so existing programs are unaffected
- `SYS_GUI_BEGIN` takes over the full screen while the desktop is active, `SYS_GFX_*`
  render into the back buffer, `SYS_GUI_FLUSH` presents it, `SYS_GUI_POLL` returns
  mouse position/buttons and a key, and `SYS_GUI_END` restores the desktop. The C
  library `<gui.h>` (TC module `gui.c`) adds `gt_panel`, `gt_button`, `gt_checkbox`,

  plus directory handles through `SYS_OPENDIR`/`SYS_READDIR`

  program returns to the shell via `SYS_EXIT`
- `.gtl` shared libraries: a loader maps the image into `LIB_BASE` (0x580000) and resolves
  exports by name through `SYS_LIBLOAD`/`SYS_LIBSYM`; the library namespace is reset for
  every program
- `.gtd` data files are read through the same fd layer (`DATA.GTD` in the demo)
- Public headers under `kernel/include/` (`gtos.h`, `unistd.h`, `stat.h`, `dirent.h`,
  `gtlib.h`, `time.h`, `stdint.h`, `ctype.h`, `stdio.h`, `string.h`, `stdlib.h`)
  are seeded onto the disk's `INCLUDE` directory

**Networking**
- RTL8139 PCI NIC driver with polled RX/TX rings (no NIC interrupts)
- Ethernet II + ARP cache; IPv4 with header checksums, automatic fragmentation on send and
  fragment reassembly on receive (2 slots, 8 KB datagrams)
- ICMP echo (`PING`) plus ICMP error handling: destination unreachable, time exceeded and
  parameter problems are recorded and surface as `-2` from `udp_recvfrom` or as a failed
  TCP send/recv (`SYS_ICMP_ERR` returns the full record for user programs)
- UDP with a DHCP client (`NET` / `DHCP`); link, MAC, IP, mask, gateway and DNS are reported
- TCP: active and passive open, MSS option, sequence/ACK, receive window,
  out-of-order segment queue and reassembly, three-duplicate-ACK fast retransmit,
  slow start / congestion avoidance / fast recovery, RST send and receive, and FIN teardown
  (`FIN_WAIT_1/2`, `CLOSE_WAIT`, `LAST_ACK`, `CLOSING`)
- Socket syscalls 21–36, plus TC builtins `ip4`, `tcp_*`, `udp_*`, `icmp_err`;
  shell clients `TCP <ip> <port> [text]` and `UDP <ip> <port> [size]`
- UDP socket table plus application protocols: DNS A-record resolver (with name
  compression), TFTP client (`RRQ`/`DATA`/`ACK` with retransmission) and an HTTP/1.0
  `GET` downloader; downloads are written into the exFAT file system
- Shell file transfer: `TFTP GET <ip[:port]> <remote> [local]` and
  `HTTP GET <host[:port]> <path> [local]`
- Default QEMU user-network address is `10.0.2.15/24`, gateway `10.0.2.2`

**Built-in C compiler (TC) & SDK**
- `TC <src.c> [more.c ...] [-o out.gtp]` compiles a C subset straight to x86-64
  machine code and writes a `.gtp` program that `RUN` can execute — no external
  toolchain involved
- Multiple sources are **flattened automatically** in the given order into one
  program: modules share the symbol table, macros and the include-once table,
  calls are resolved after every module is parsed, and each module still uses
  its own directory for `#include "..."`
- Optimization: `-O0`..`-O4` (`-Os`, `-Ofast`), with per-pass switches
  `-fconst/-fno-const`, `-fstrength/-fno-strength`, `-fdce/-fno-dce`,
  `-floop/-fno-loop`, plus `-g` (debug, resets to O0) and `-v` (print the
  effective flags and code/data sizes). Flags link: `-fdce` implies folding,
  `-floop` implies `-fdce`, `-fno-const` disables every pass, and later flags
  win over earlier ones. Passes: O1 constant folding + immediate operands,
  O2 strength reduction (shifts, unsigned div/mod by powers of two), O3
  constant-`if` dead-branch elimination, O4 constant-loop elimination
  (`while(0)`, `while(1)`, `do..while(0/1)`). All levels use direct
  local-variable access (`mov [rbp+d]` without a `lea`/stack round-trip),
  shortest immediate encodings (`xor`, `imm32`, `imm8` forms), and emit
  `cmp` + `jcc` directly for conditions instead of materialising 0/1.
  Binary/assignment/incdec/subscript temporaries live in `r11`/`r10`
  (constant right operands defer the save; only deeper expressions spill to
  the stack), and a `for`-step `i++` becomes an in-place memory increment;
  the benchmark code is 2091 bytes at `-O0` and 1846 at `-O4`
- Supported: `int`/`char`/`double`/pointers, 1-4D arrays, `struct`/`union` (fields,
  nested structs, `.` and `->`, bitfields), function pointers and function-pointer
  arrays, functions (up to 6 parameters, recursion, prototypes, user variadic
  `...` with `va_list`/`va_start`/`va_arg`/`va_end`), `if/else`, `while`,
  `do/while`, `for`, `switch/case/default` (fallthrough),
  `break`/`continue`/`return`/`goto` with labels, full expressions (signed and
  `unsigned` integer plus `double` arithmetic/comparison) with `?:`,
  prefix/postfix `++`/`--`, compound assignments, `typedef`, `enum`,
  `sizeof(type)`/`sizeof expr`, casts, string/char literals with escapes
  (`\n \t \xNN \NNN`), and brace/string initializers for globals and locals
- Object-like and function-like `#define` macros (including `#` stringizing and
  `##` token pasting) are expanded by the scanner; `#if` is not implemented
  (GT-DOS only targets one platform), and other directives are skipped.
  `#include <...>` / `#include "..."` is resolved at compile time (source
  directory, `\SDK`, then `\GT-DOS\INCLUDE`); each file is included once. Standard
  modules (`string/stdlib/ctype/stdio/net`) are compiled into the program **only when their
  header is included**, so unused library code never bloats `out.gtp`
- Network library: `NET.H`/`NET.C` (on demand) adds `net_aton`, `net_resolve`
  (dotted decimal or DNS), `net_connect`, `net_send_str`, `net_send_all`,
  `net_recv_line` and `net_recv_all` on top of the TCP/UDP builtins
- Standard library: `strlen strcpy strncpy strcmp strncmp strcat strncat strchr strrchr
  strstr memcpy memmove memset memcmp`, `malloc calloc free strdup abs atoi strtol rand
  srand` (16 KB heap),
  `isdigit isalpha isalnum isspace isupper islower toupper tolower`,
  `printf putchar puts getchar`; `printf` is a compiler builtin (SYS_PRINTF) supporting
  `%d %i %u %x %X %c %s %p %f %%` with up to 5 varargs
- Not supported: `long double`, functions returning function pointers, and `#if`
  conditionals
- Builtins (`\SDK\TC.H`): `putc`, `print`, `print_int`, `getc`, `exit`, `sleep`,
  `uptime`, `open`, `read`, `write`, `close`, `seek`, `stat`, `statx`, `reboot`, `shutdown`;
  console/system calls `cls`, `color`, `screen`, `getcwd`, `hostname`, `username`,
  `isadmin`, `version`, `unixtime`, `rich`; filesystem `unlink`, `mkdir`, `rmdir`;
  `\SDK\NET.H` adds `ip4`, `tcp_connect`, `tcp_send`, `tcp_recv`, `tcp_close`,
  `dns`, `tftp_get`, `http_get`
- SDK at `\SDK\` (plain, read-only): `TC.H`, `STRING.H`, `STDLIB.H`, `CTYPE.H`,
  `STDIO.H`, `STDARG.H`, `NET.H`, `STRING.C`, `STDLIB.C`, `CTYPE.C`, `STDIO.C`,
  `NET.C`, `HELLO.C`, `HELLO.S`, `FIB.C`, `THREAD.C`,
  `README.TXT`; `PUT` + `APPEND` let you author sources line by line inside GT-DOS
- Program layout: 128 KB code at `0x600000`, 128 KB data at `0x620000`
  (64 KB globals + 64 KB string pool)

**Built-in assembler (ASM)**
- `ASM <src.s> [-o out.gtp]` encodes a NASM-style single-file x86-64 source into
  a `.gtp` with the same layout as TC (code at `0x600000`, data at `0x620000`),
  ready for `RUN`
- Syntax: `.text`/`.data` (or `section ...`), labels, `equ` constants,
  `db/dw/dd/dq`, `times`; 64-bit `rax..r15` and 32-bit `eax..r15d`; memory
  operands `[reg]`, `[reg+disp]`, `[reg+index*scale+disp]`, `[label]`, `[disp]`
- Instructions: `mov lea add sub and or xor cmp test inc dec neg not imul
  div idiv shl shr sar push pop call ret jmp jcc int nop hlt leave cqo cdq`;
  `je/jne/jl/jle/jg/jge/jb/jbe/ja/jae/js/jns` use rel32 branches
- Entry is code offset 0; call the kernel via `INT 0x21` (`rax` = call number)
  and exit with `rdi`=code, `rax=0`; see `\SDK\HELLO.S`

**Multithreading**
- Round-robin scheduler: the main thread plus up to 7 children, each with its
  own 12 KB stack; the 100 Hz timer preempts every 5 ticks (≈50 ms) and threads
  may also yield (TC `yield()` emits `INT 0x2F` directly, skipping the syscall
  gate)
- Blocking waits: `thread_join(tid)`, `mutex_lock(id)` and `sleep(ms)` put the
  caller in BLOCKED state; exit/unlock wake the waiters and the timer handles
  sleep deadlines
- Kernel mutex objects (up to 16): `mutex_create()`, `mutex_lock(id)`,
  `mutex_unlock(id)`, `mutex_trylock(id)` (0 / ‑2 reentrant / ‑3 busy) and
  `mutex_destroy(id)`; a mutex owned by an exiting thread is released and its
  next waiter woken. The `stdlib` malloc heap is mutex-protected (lazy creation
  inside a critical section) so threads can share it
- Critical sections: `critical_enter()` / `critical_exit()` suspend timer
  preemption (nestable) for short cross-instruction shared-data updates
- Stability: a child fault (divide-by-zero, bad access) only terminates that
  thread (`join` returns ‑1) and the system keeps running; main-thread faults
  still dump state and halt. Per-thread stack guards/overflow detection, and
  xmm0–7 plus MXCSR are saved across switches
- Threads run in ring0 and share the program address space and globals; timer
  preemption is disabled while a system call runs, so console, file and network
  calls stay atomic; thread ids restart at 2 for each program
- TC builtins: `thread_create(fn, arg)` → tid (51), `yield()`, `thread_exit(code)`
  (53), `thread_join(tid)` (54), `gettid()` (55), `mutex_*` (56–58, 62, 63),
  `thread_detach(tid)` (59), `critical_enter/exit` (60/61);
  see `\SDK\THREAD.C`; the shell's `THREADS` command dumps the thread table
- Entry functions receive the argument with TC's calling convention (on the
  stack); `exit()` in a child only ends that thread, and the kernel reaps all
  threads a program created when it exits; detached threads need no join
- Limits: no priorities or condition variables, and threads share one address
  space (ring0, no isolation) — protect shared data with mutexes or critical
  sections

**GUI desktop and mouse**
- After login GT-DOS enters the graphical desktop automatically
  (`gui_default=1` in `GTOS.CFG`); `CONFIG GUI OFF` disables it, and
  `DESKTOP` / `GUI` re-enters on demand; `TEXTMODE`, the bottom-right `TEXT`
  button or the title-bar `x` returns to plain text (documented in help)
- The desktop is drawn above the graphics console: gradient wallpaper, rendered
  desktop icons (`TERM` = mini terminal, `FILES` = folder, `SYS` = chip),
  a centred terminal window (title bar, `M` maximize/`R` restore, close button)
  and a taskbar with a `GT-DOS` start button, caption and a running clock
- Start menu (click the `GT-DOS` button): `Terminal` closes the menu, `Theme`
  cycles three wallpaper palettes, `About` opens a modal dialog, `Settings`
  opens the control panel, `Widgets` opens the control demo and `Exit GUI`
  returns to plain text
- Settings panel (modal, close with `Close` or a click outside): `<` / `>`
  theme buttons, a `Desktop icons` checkbox, a `24-hour clock` checkbox
  (unchecked shows a 12-hour clock with AM/PM) and a draggable `Brightness`
  slider that dims the wallpaper
- Widgets panel (start menu `Widgets`): a radio group for the wallpaper theme,
  an animated progress bar and a selectable list; the same control set is
  available to C programs through `<gui.h>` (see the system-call section)
- `vga_gui_viewport` clips the text grid to the window client area, so the
  window still hosts the complete shell, TC programs and the editor with the
  normal console cursor and scrolling
- Window dragging: hold the title bar (except the buttons) and move; the
  window is clamped above the taskbar and the console viewport moves with it;
  maximizing fills the screen above the taskbar and restoring returns to the
  previous position/size; dragging the grip in the bottom-right corner
  resizes the window (minimum 40×12 text cells, clamped to the screen)
- PS/2 mouse: 2× acceleration at ≥1280 wide; the pointer is the classic arrow
  (12×19 white body with a black outline, exact per-pixel bitmap) and scales
  with the font. It is written straight to video memory and repainted
  immediately after every console commit (no overwrite flicker); movement
  restores the old area from the back buffer, so window content, menus and
  dialogs are never polluted
- `python build.py run` uses `gtk,grab-on-hover=on,show-cursor=off`: the mouse
  is captured on hover and the host pointer hidden, avoiding double-cursor
  flicker and pointer escape at the window edges; `Ctrl+Alt+G` releases it
- Requires VBE graphics; if only the VGA text fallback is available, `GUI`
  reports that the desktop is unavailable

**Rich text and editor**
- `CAT [-n] <file...>` concatenates one or more files; `-n` adds continuous line numbers
- `RICH <file.md>` renders Markdown with ANSI/VGA colours: ATX and Setext headings,
  bold/italic/bold-italic/strikethrough, inline code, links and images, nested
  lists (ordered/unordered/task), nested quotes, horizontal rules, fenced code
  blocks with lightweight C-family highlighting, and tables with automatic column
  widths and `:---:`/`---:` alignment; inline tags `<b> <i> <c=red> </c> <br>`
  are also understood
- Programs can render Markdown through `SYS_RICH` (TC builtin `rich`), and read the
  terminal size via `SYS_SCREEN`
- `VIM <file>` is a full-screen modal editor (normal/insert/command/search) with arrows,
  Home/End/PgUp/PgDn, `i I a A o O`, `x X`, `dd`, `yy`, `p`, one-level `u`, `gg/G`,
  `w/b` word motion, `J` join, `D` delete-to-EOL, Ctrl+D/Ctrl+U half-page scroll,
  `/text` + `n`, `:w :q :q! :wq`, line numbers and a status bar; files up to 256 KB,
  editing uses the program scratch region and returns to the console on exit
- `.c/.h/.cpp` files are shown with C syntax highlighting (preprocessor, comments,
  strings, chars, numbers, types and keywords), honouring horizontal scroll and tabs
- `\SDK\DEMO.MD` is a ready-made rich-text sample

**exFAT vendor extension**
- Each file/directory entry set carries three vendor entries (type `0xE0`):
  encryption metadata (flag, algorithm, plaintext size, CRC32), ACL (owner and mode bits),
  and version + CRC32
- `SYS_STATX` exposes them to programs (`flags`/`version`/`crc`/`owner`/`mode`);
  the kernel enforces the owner on writes by non-admin users

**Security**
- Every file under `\GT-DOS\` is stored AES-128-CBC encrypted (PKCS#7 padding); the kernel
  decrypts transparently for its own use
- The kernel is a protected program: a `.container` trailer (`GTK1`) stores its length,
  CRC32 and SHA-256, and `kernel_self_check()` verifies the loaded image before anything
  else runs. `KERNEL` prints the verified digest and compares it against the encrypted
  `\GT-DOS\KERNEL.GTP` view; `RUN` refuses to execute that image.
- Runtime anti-tampering: the code/rodata range is 4 KB read-only (CR0.WP), re-checked by
  the idle watchdog every 5 seconds and on demand with `KERNEL VERIFY`; any mismatch halts
  the system.
- Every `.gtp` program is CRC32-checked against its exFAT vendor metadata before control is
  transferred, so a tampered or corrupted program is rejected.
- Format parsers live in Rust (`rust/gtcore`: `parse.rs`, `sha256.rs`): `.gtl` headers and
  exports, `.gtd` glyph lookup, `.gtp` integrity and exFAT directory entries; the C side
  keeps only memory mapping and jumps.
- The cipher and CRC32 are implemented in Rust (`rust/gtcore`, `no_std`) and linked into the
  kernel; the build-time formatter `rust/gtmkfs` uses the same crate for encryption
- Image formatting, directory entries and vendor extensions are produced entirely by the
  Rust tool `rust/gtmkfs`; the build script only writes a seed manifest and invokes it once
- System files are strictly protected: no account, including `admin`, may read, modify or
  delete them (`TYPE`/`HEAD`/`WC`/`CP`/`MV` refuse, writes and deletes are blocked)
- Non-admin users can only write inside their own home directory (`\USERS\<name>\`)
- Privileged commands (`USERADD`, `USERDEL`, `HOSTNAME`, `CONFIG RESET`, `OOBE`, `MOUNT`,
  `DIV0`, `RUN`, `REBOOT`, `SHUTDOWN`) require administrator
- Compiler stack protection (`-fstack-protector-strong`) and bounds assertions (`GT_ASSERT`)

## Quick Start

### Requirements

| Dependency | Notes |
| --- | --- |
| Windows | The build script and font generator use Win32 APIs |
| Python 3.8+ | Runs `build.py` |
| Rust (stable) | `cargo` on `PATH`; the bare-metal target `x86_64-unknown-none` must be installed (`rustup target add x86_64-unknown-none`) |
| NASM | `nasm.exe` on `PATH`, or in `C:\Program Files\NASM` |
| LLVM / clang | `clang.exe`, `ld.lld.exe`, `llvm-objcopy.exe` in `D:\LLVM\bin` or `C:\Program Files\LLVM\bin` |
| QEMU | `qemu-system-x86_64.exe` in the `qemu/` directory, or on `PATH` |

`build.py` searches the locations listed in `CANDIDATES`; adjust that table if your toolchain
lives somewhere else.

### Build and run

```sh
python build.py            # compile, producing build/gt-dos-hd.img
python build.py run        # boot the image in QEMU
python build.py run -nogui # serial console only, no graphics window
python build.py run -full  # full-screen window (resolution auto-selected)
python build.py run -debug # boot with CPU/interrupt tracing enabled
python build.py all        # build, then run
python build.py clean      # remove the build directory
```

The first build also generates the font: the Rust tool `rust/mkfont` is built and invoked
automatically when `build/font.gtd` or `build/cpm.gtd` is missing. Kernel C/assembly
translation units are independent, so `build.py` compiles them in parallel (one worker
per CPU) and links them afterwards.

To boot the released image directly:

```sh
qemu-system-x86_64 -hda gt-dos-hd.img -boot c
```

On first boot the OOBE wizard asks for language, hostname and administrator name.
Empty input re-prompts; `Ctrl-C` skips a step with its default value.

## Disk Layout

The image is a single 64 MB raw hard disk with an MBR partition table:

| Region | Location | Contents |
| --- | --- | --- |
| MBR | LBA 0 | `boot/mbr.asm`, partition table written by `build.py` |
| Partition 1 (C:) | LBA 2048, 120832 sectors | exFAT system volume, holds `\GT-DOS\` and the `INCLUDE` headers |
| Partition 2 (hidden) | last 8192 sectors | Boot partition, type `0x11`, bootable: `boot.gtb` + `kernel.gtb` + `font.gtd` + `cpm.gtd` |

The boot partition sits at the end of the disk and carries the bootable flag; the kernel reads
`font.gtd` and `cpm.gtd` from it at boot time over ATA.

Binary artifacts use GT-DOS semantic suffixes: `.gtb` for raw loader/kernel binaries
(`mbr`/`boot`/`kernel`), `.gtd` for data blobs (`font`/`cpm`/`data`), `.gtp` for user programs
(`hello`/`demo`) and `.gtl` for shared libraries (`sample_lib`).

## Shell Commands

Type `HELP` (or `?`) inside GT-DOS for the full list. Commands support both long and short names.

**System** — `HELP`/`?`, `VER`, `CLS`, `DATE`, `TIME`, `MEM`, `KERNEL`, `CPUID`, `UPTIME`,
`BEEP`, `COLOR`, `SERIAL [OFF]`

**Users** — `WHOAMI`, `USERS`, `LOGIN`, `LOGOUT`/`EXIT`, `PASSWD`, `USERADD`, `USERDEL`,
`HOSTNAME`, `CONFIG`, `OOBE` (administrator privileges required for `USERADD`, `USERDEL`,
`HOSTNAME`, `SHUTDOWN` and `REBOOT`)

**Files and disks** — `CD`, `PWD`, `DRIVES`, `DIR`/`LS [/A]`, `TYPE`, `CAT [-n] <f...>`,
`RICH <f.md>`, `VIM <f>`, `PUT`, `DEL`/`RM`, `MKDIR`/`MD`, `RMDIR`, `TOUCH`, `ATTRIB`,
`CP`/`COPY`, `MV`/`REN`, `HEAD`, `WC`, `TREE`, `DF`, `DISK`, `MOUNT`, `APPEND`

**Display and hardware** — `APIC`, `IRQSTAT`

**Network** — `NET`, `DHCP`, `PING <ip> [count]`, `TCP <ip> <port> [text]`,
`UDP <ip> <port> [size]`, `DNS <name>`, `TFTP GET <ip[:port]> <remote> [local]`,
`HTTP GET <host[:port]> <path> [local]`

**Programs** — `RUN <file.gtp>` (administrator privileges required),
`TC <src.c> [more.c ...] [-o out.gtp]` (C subset compiler, multi-module flattening),
`ASM <src.s> [-o out.gtp]` (x86-64 assembler)

**Tasks and services** — `TASKS`/`PS`, `SERVICE LIST`, `SERVICE RUN <name>`,
`SERVICE STOP <name>`

**Power** — `REBOOT`, `SHUTDOWN`/`POWEROFF` (administrator privileges required)

## Keyboard

PS/2 set-1 driver with E0 extended keys: arrows, Home/End, PgUp/PgDn and Ins/Del.
Ctrl combinations become ASCII control codes, so `Ctrl+C` cancels the current line,
`Ctrl+A`/`Ctrl+E` jump to its start/end, and `Ctrl+P`/`Ctrl+N` walk the history.
`Ctrl+Up`/`Ctrl+Down` scroll the console, `Ctrl+Alt+Del` reboots.
`NumLock` is on by default, so the keypad types digits/operators out of the box; with
NumLock off it becomes navigation (Home/End/PgUp/PgDn/Ins/Del). The keypad `Enter`,
`+ - * / .` keys work too, and CapsLock/NumLock LEDs follow the driver state.

## Tasks and System Services

- Kernel subsystems (`kernel.core`, `kernel.image`, `net.stack`, `fs.exfat`, `tty.console`,
  `crypto.aes`) are registered as SYS tasks at boot; `TASKS`/`PS` lists ID, type (SYS/USR),
  protection flag, name, state, memory and owner.
- `kernel.image` represents the `GTK1` container; `KERNEL` shows its verified size, CRC32,
  SHA-256 and whether `\GT-DOS\KERNEL.GTP` still matches the running image.
- System services are ordinary `.gtp` programs under `\GT-DOS\SERVICES\`, seeded encrypted at
  build time (for example `NETSVC.GTP`). `SERVICE RUN <name>` executes one; because the file
  lives under `\GT-DOS\`, the running program is registered as a SYS task.
- SYS tasks and service files are protected: `SERVICE STOP` refuses, and `DEL`/`ATTRIB`/`CP`
  on `\GT-DOS\` paths are rejected.

The test scripts drive a QEMU instance over a serial socket and a QEMU monitor socket, so they
assert on real boot output rather than on mocks.

`tools/test_perf.py` compiles and runs `\SDK\BENCH.C` inside GT-DOS at both
`-O0` and `-O4`, runs the same workloads natively (`rustc -O`) and writes
`build/perf_report.md`. On the QEMU test host the benchmark's code section is
2091 bytes at `-O0` and 1846 at `-O4`; the integer loop is ≈50 ms, the
constant-expression loop is ≈1.2–1.6× faster at `-O4` (70→50 ms) and array
indexing ≈60 ms (5M iterations, 10 ms timer resolution). Programs remain 14–150× slower than native depending on the
workload — mostly QEMU TCG emulation plus TC's simple code generation (values
live in stack slots, no register allocation).

## Notes and Limitations

- The kernel currently fits in 593 sectors (303,472 bytes including the 48-byte `GTK1`
  trailer); the build cap is 640 sectors (320 KB), loaded between `0x10000` and `0x60000`.
  The linker also asserts `.bss <= 0xA0000` and `.highbss <= LIB_BASE`.
- The GDT is built in low memory (0x6800) rather than `.data`: loading a segment register
  sets the descriptor's accessed bit, which would otherwise invalidate the kernel hash.
- The boot hash covers the whole image (code + rodata + data); the runtime watchdog only
  covers the immutable `[0x10000, __ro_end)` range, because `.data` legitimately changes.
- Large zero-initialised buffers (`font_buf`, the code page table, the back buffer) are placed in
  a `NOLOAD` `.highbss` section above 1 MB. If they were in ordinary `.bss` they would overlap the
  `0xA0000` VGA aperture and corrupt the framebuffer.
- TC implements a practical C subset: arrays, structs/unions (with bitfields),
  `switch`, `?:`/`++`/`--`, `typedef`/`enum`/`sizeof`, casts, function pointers,
  user-defined variadic functions and `double` arithmetic are supported; `#define`
  macros and `#include` are expanded at compile time, and the matching standard-library
  module is linked on demand. `long double` and `#if` are unsupported. Programs are
  limited to 128 KB of code and 128 KB of data (64 KB globals + 64 KB strings).
- Kernel `.bss` must stay below `0xA0000` (the VGA aperture) and `.highbss` below
  `LIB_BASE`; the linker script asserts both bounds, so oversized tables fail the build.
- Shell file commands (`TYPE`/`CP`/`MV`/`HEAD`/`WC`/`APPEND`) operate on files up to 64 KB.
- The network stack is IPv4-only (no IPv6) and has no SACK or window scaling;
  `TCP_ACCEPT` handles one connection per listening socket; UDP datagrams are limited
  to 8 KB by the reassembly buffer.
- TFTP/HTTP downloads are buffered in RAM and limited to 64 KB per file.
- Building requires Windows; the kernel itself is fully freestanding and does not depend on the
  host platform.
